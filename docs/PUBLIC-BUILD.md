# Reviewing and rebuilding this source snapshot

The original environment is Ubuntu 24.04 in WSL `A51-KernelBuilder`, with isolated work under `/opt/a51-hakios`. The host repair used the common source at `ae617cf381316111d5ad25b05040e5b28e1052ee` from `speedyg2200/hakios-xnu-kernel`, plus local adaptations. `platform/` is the exported current common/device tree, rather than a clean upstream commit. Exact dependency revisions/remotes are in `manifests/current-sources.json`; each published file is hashed in `PUBLICATION-MANIFEST.json`.

Use a separate checkout/work directory. Supply the pinned external sources and required licensed SDK/runtime locally. Follow `platform/README.md`, `platform/xnu-deps/setup.sh`, `platform/xnu/apply.sh` and `platform/xnu-build.sh` for the common build environment. Do not assume source snapshots alone include an installable runtime.

`patches/current-xnu.patch` describes the current generated/native tree against the pinned pristine Apple XNU commit recorded in the manifest. Apply it to that pristine native checkout, rather than stacking it on top of `platform/xnu/apply.sh`'s already patched tree. It includes generated driver/library additions; vendor firmware is excluded. Earlier Phase 3/4 patches use a different historical prepared baseline and are preserved separately under their original names.

The supplemental v3 repair script reuses preserved v2 build inputs, working userland objects, UEFI, init and Iris executable. Its full rebuild prerequisites and command sequence are in [the repair record](AUDIO-IRIS-REPAIR-20261124.md). Adjust hardcoded Windows/WSL paths and create a new packet before reuse; `prepare` and export deliberately refuse overwriting existing evidence/images. Future full userland builds must select `RC_JOBS=rc.jobs.audio-iris` to include Iris registration. Iris's own build requires the separately supplied iPhoneOS16.5 SDK and toolchain.

The host parser/native models cannot qualify a phone image. `scripts/run.py` records exact consequential command arguments, output, status and times. The retained device/flash/restore tools require local image/rollback inputs and matching-device pins. Publication sanitizes the personal serial to `A51_SERIAL_HERE`; replace it with the intended verified device only when conducting an authorized installation. Never reuse another device's partition pins without checking them.

Known limits: the kernel wrapper accepts a linked image even when preexisting kext symbol-set checks report exit2; QEMU's passing test uses raw hello, not final md0/md1, and disables A51 audio; current speaker and Iris observations are pending. Generated phone images and full raw evidence remain local and cannot be replayed from this repository alone.

Local UEFI experiments are exported as source overlays under `port/current-uefi/`. Copy each overlay to its matching pristine Mu-Silicium/Mu_Basecore revision in `manifests/current-sources.json`, preserving file paths; supply excluded resources separately. These overlays are independent older experiments and were not rebuilt or used for v3.
